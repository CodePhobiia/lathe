    Examples catalog¶

    Index of every runnable .lth source under examples/. Asset-oriented files parse via lathe check; Wonder scene-source bridge files are validated with lathe scene source-to-scene-graph because their embedded Scene Graph payload is the durable source of truth. Certification (lathe build ... --out ... + validate/report.json certified == True) is tracked per-row where an asset build exists.

    Build times assume a local .venv with xatlas/manifold3d installed, native shape provider, no remote runtime config.

    Complexity tiers:

    • T0 — canonical hero (8+ parts, full surface program, full assembly).
    • T1 — compact variant of a hero (renamed asset, same part graph).
    • T2 — feature-focused API demo (highlights a specific language surface).

    CI coverage¶

    .github/workflows/examples.yml has three jobs:

    • check — lathe check every API and corpus example on PR (fast, ~2s/file).
    • build-nightly — full build + certification on the API and corpus example suite, runs on the cron schedule (and manual dispatch).
    • corpus-pytest — runs tests/unit/test_example_corpus.py on every PR so certification regressions show up before nightly.

    Artifacts uploaded: build_report.json, selector_manifest.json, and stages/validate/report.json for every asset built.

    Authoring a new example¶

    1. Pick the closest hero family in std/families/.
    2. Copy examples/<hero>.lth and rename the module, the top-level asset, and the registry path. Keep parts, assembly.components, and seam_classes aligned with the family blueprint — those drive part_coverage and adjacency_score during certification.
    3. Run python -m lathe.cli check <file> — must return ok=True.
    4. Run python -m lathe.cli build <file> <asset> --out tmp_out and inspect tmp_out/<asset>/stages/validate/report.json.
    5. Add an entry to this catalog and to EXPECTED_CERTIFY in tests/unit/test_example_corpus.py.
