    def to_dict(self) -> dict[str, Any]:
    """To dict.

    Returns:
        The result.
    """
    payload = asdict(self)
    payload["primitives"] = [primitive.to_dict() for primitive in self.primitives]
    payload["regions"] = [region.to_dict() for region in self.regions]
    return payload

    ShapePrimitive.

    Currently supported primitive_type values:

    • "box": axis-aligned cuboid; uses extents (full, not half).
    • "cylinder": round cylinder along axis; uses radius + height.
    • "sphere": round solid centered on center; uses radius. This is the smallest organic/soft-form primitive in the stable ShapeIR vocabulary and is used for domes, foliage masses, bulbs, rounded caps, soft props, and any component that should not be coerced into a box or cylinder.
    • "capsule": a cylinder with hemispherical end caps along axis; uses radius plus total length. This is the stable rounded-strut vocabulary for handles, limbs, hoses, rails, pads, and ergonomic mechanical forms that should not collapse into three unrelated cylinder/sphere parts.
    • "revolved_profile": solid of revolution around axis through center, defined by profile_points as a list of (axial, radial) 2D points (cm). By default the profile is revolved 360 degrees to produce a watertight, radially-symmetric mesh; optional revolve_degrees and revolve_start_degrees can emit capped partial revolves for fan guards, knobs, cutaway collars, and crescent-shaped hard-surface details that a full lathe cannot express.
    • "extruded_profile": linear extrusion of a 2D polygon along axis through center, defined by profile_polygon as a CCW list of (u, v) 2D points in the cross-section plane perpendicular to axis, swept extrude_height along axis. Produces watertight prismatic geometry — the deterministic vocabulary for hard-surface features with a constant cross-section that the box+cylinder vocabulary cannot express: picatinny rails, magazine bodies, trigger groups, charging-handle slots, plate stocks, etc.
    • "torus": ring solid centered on center with ring axis axis, defined by major_radius (distance from the ring center to the center of the tube) and minor_radius (tube radius). Closes the gap between cylinders and full revolved profiles for ring-shaped features such as trigger guards, sling loops, scope rings, and cap collars where authoring an entire profile polyline would be overkill.
    • "tube": a straight hollow cylinder along axis with outer_radius, inner_radius, and height. It preserves annular rims, bores, sockets, barrels, collars, and pipe sections as one semantic primitive instead of a subtractive cylinder pair.
    • "gear": an extruded involute-style spur/helical gear with teeth, pitch_radius, thickness, optional bore, and tooth profile controls. It preserves mechanical tooth intent as a semantic primitive instead of an anonymous extruded polygon.
    • "flange": an annular mounting plate with optional straight bolt-circle holes. It uses outer_radius, inner_radius, thickness, optional bolt_count, bolt_radius, bolt_circle_radius, start_angle_degrees, and rim_bevel. It preserves mechanical mounting intent as one semantic primitive instead of an anonymous tube plus repeated subtractive cylinders.
    • "rounded_slot": a capsule-ended slot cutter/solid with length, width, depth, axis, and optional rotation_degrees. It preserves slotted-hole intent instead of lowering immediately into an anonymous extruded profile.
    • "socket": a semantic seating/clearance cutter or solid for component integration. Uses socket_shape/style plus clearance, width, height, depth, optional radius, length, axis, and rotation_degrees to preserve round, rectangular, and capsule socket intent instead of erasing it into anonymous cylinder/profile cutters.
    • "countersunk_hole": a straight, countersunk, or counterbored cylindrical bore cutter generated from radius, depth, style, and optional sink/bore shoulder dimensions. It keeps hole style intent visible to the kernel instead of erasing it into a generic revolved profile.
    • "countersunk_hole_set": repeated straight, countersunk, or counterbored bore cutters sharing one style/dimension definition. Uses hole_centers, radius, depth, axis, style, and optional sink/bore shoulder dimensions so screw-hole patterns survive as one semantic cutter field.
    • "panel": a rectangular or rounded rectangular plate generated from width, height, thickness, axis, optional rounding, and corner_segments. It preserves panel intent instead of erasing the source into a generic extruded polygon.
    • "panel_frame": a rectangular frame/ring generated from width, height, border_width, thickness, and frame axes. It preserves framed-panel intent as one semantic primitive instead of four unrelated box bars.
    • "panel_line_cut": a semantic rectangular groove/cutter generated from length, width, depth, length_axis, width_axis, and normal_axis. It preserves panel-line/groove intent for hard-surface seams instead of erasing it into an anonymous extruded profile.
    • "inset_cut": a semantic shallow face-recess cutter generated from a source envelope or explicit extents. It preserves inset/recess intent, side, normal axis, and margin instead of lowering directly to an anonymous box.
    • "ribbed_panel": a panel with repeated raised stiffener ribs. It uses width, height, thickness, rib_count, rib sizing/profile fields, optional cross ribs, and axis controls so reinforced hatches and sci-fi plates stay one semantic construct.
    • "perforated_panel": a rectangular or rounded plate with a grid/staggered grid of circular or rounded-slot through-holes. It keeps grate, vent, and armor-perforation intent visible as one semantic primitive.
    • "fastener_grid": a repeated washer/head hardware grid generated from row/column counts, spacing, radius, head style, washer controls, normal axis, and row/column axes. It keeps purposeful bolt/rivet detail as one semantic construct instead of loose cylinders or revolved-profile instances.
    • "weld_seam": a semantic weld bead generated either along an explicit path or along a straight axis. Uses weld_mode, width, radius, cross_section/sweep_path for path welds, or length/axis for straight welds so attachment seams remain weld intent instead of anonymous swept/extruded profiles.
    • "edge_chip_set": a repeated set of spherical edge/corner chip cutters generated from a source envelope, selected corner signs, and chip radius. It preserves damage intent as one semantic operation instead of unrelated subtractive spheres.
    • "dent_mask_set": a repeated set of spherical dent cutters placed on a source face. Uses dent_centers, radius, depth, normal_axis, and side so impact/damage masks remain a coherent semantic field instead of unrelated spheres.
    • "surface_patch_set": a repeated set of rectangular surface patches or shallow groove cutters. Uses patch_centers, patch_kind, length, width, depth/thickness, and tangent axes so scratches, grime strips, and similar surface detail remain one semantic field instead of unrelated boxes.
    • "structural_beam": an extruded structural section such as an I-beam, C-channel, U-channel, L-angle, or T-beam. It uses length, width, height, profile_shape, web_thickness, and flange_thickness so supports and frames remain semantic instead of becoming anonymous extruded polygons.
    • "rail": an extruded mechanical rail section such as square, rectangular, dovetail, trapezoid, or T-slot. It uses length, profile, profile_height, profile_shape, and optional shape-specific width controls so guide rails, machine tracks, and keyed mounts remain semantic kernel primitives.
    • "louver_panel": a framed panel with repeated angled slats. It uses width, height, thickness, slat_count, slat sizing/angle fields, and optional axis controls so vent grilles, shutters, heat exchangers, and sci-fi panels stay one semantic visible construct instead of loose boxes and anonymous extrusions.
    • "vent_slats": a repeated rectangular slat array generated from slat_count, slat_spacing, length, height, thickness, normal axis, row axis, and length axis. It preserves vent/readable-secondary-detail intent without exploding the common case into anonymous box records.
    • "ladder_frame": two side rails plus repeated rungs, generated from length, width, rail_radius, rung_count, optional rung radius/spacing/span controls, and axis fields. It preserves rail-and-rung frame intent as one semantic construct instead of a loose set of cylinders.
    • "truss_frame": chords, posts, diagonal braces, and optional depth ties generated from length, height, depth, member_radius, bay_count, bracing pattern, and axis fields. It keeps structural-frame intent as one semantic primitive.
    • "support_bracket": an L-style mounting bracket with vertical plate, foot plate, and optional triangular gussets. It uses width, height, depth, thickness, bracket axes, and gusset controls so attachment support intent survives kernel execution as one construct.
    • "trim_band": a visible raised or subtractive rectangular strip generated from length, width, thickness, and axis controls. It preserves trim/detail hierarchy intent instead of reporting the strip as a generic box.
    • "corner_guard_set": repeated protective corner bars generated from a source envelope, selected axes, corner signs, guard size, thickness, and seat depth. It preserves hardware-corner intent as one semantic primitive instead of many anonymous box bars.
    • "hinge": a mechanical barrel hinge with two leaves, center pin, and alternating knuckles. It uses length, leaf_width, leaf_thickness, barrel_radius, pin_radius, knuckle_count, knuckle_gap, and hinge/leaf axes so hardware intent survives as one kernel primitive instead of loose boxes and cylinders.
    • "handle": a U-pull or grab handle with swept grip and mount pads. It uses span, standoff, grip_radius, pad_radius, pad_thickness, span/normal/cross axes, and segment controls so hardware attachment intent remains one primitive.
    • "subdivision_box": axis-aligned cuboid with per-corner controllable rounding radii. Generalizes the uniform rounding knob on "box" so each of the 8 corners gets its own radius (zero ⇒ sharp). Uses extents and center like a box, plus corner_radii (8-tuple) and corner_segments for mesh density. Order of corners follows (-x-y-z, +x-y-z, -x+y-z, +x+y-z, -x-y+z, +x-y+z, -x+y+z, +x+y+z) so authors can round one face/edge/corner without touching the others — receivers with rounded backs / sharp fronts, stocks with chamfered buttplates, magazine wells with eased entry corners.
    • "swept_profile": a 2D cross_section polygon swept along a 3D sweep_path polyline through center. The cross-section's local Y aligns with the path tangent at each frame; the local X/Z span the perpendicular plane. This is the most general curved vocabulary in the kit — covers ergonomic stocks, curved barrel shrouds, hose-like trim, sling cables, and contoured rail covers that a single straight-axis revolve cannot express.
    • "helical_sweep": a compact helix generator for coils, springs, thread ridges, hoses, and cable wraps. It uses radius, height, turns, axis, optional tube_radius or an authored cross_section, plus segments_per_turn, cross_section_segments, phase_degrees, and handedness. It preserves the helical construction parameters instead of expanding intent immediately into a large sampled sweep_path.
    • "threaded_cylinder": a single analytic external-thread cylinder primitive generated from radius, height, thread_pitch, thread_depth, turns, axis, handedness, phase, clearance, and profile-shape controls. It preserves fastener/thread intent as one kernel construct instead of lowering first to a cylinder plus loose helical ridge geometry.
    • "curved_tube": a compact circular-arc pipe/elbow generator for hoses, bent rails, conduits, exhausts, handles, and hard-surface routed tubes. It uses radius (arc centerline radius), tube_radius, angle_degrees, plane_axis, optional start_angle_degrees, optional inner_tube_radius for a hollow shell, plus path/cross-section segment controls. It preserves analytic bend intent instead of immediately expanding the part into a generic sampled swept_profile.
    • "heightfield": regular 2D grid of elevation samples laid out in the XY plane and lifted along the world-up axis. Defined by resolution ((nx, ny) cell counts), height_data (a nested list of ny rows × nx columns of floats), bounds_xy ((xmin, ymin, xmax, ymax)) and vertical_scale (multiplier applied to height_data before emitting Z). Each cell becomes two triangles; UVs are the lattice coordinates and normals come from the height gradient. This is the first-class data type consumed by the §7.2 terrain pipeline (Tu-Pham hydraulic + thermal erosion + biome layering) and produces the slope, flow, and deposition masks downstream surface_graph layers depend on.
    • "terrain_patch": a semantic terrain primitive backed by the same regular heightfield payload, preserving biome/erosion/terrain intent while emitting explicit heightfield triangles for downstream stages.
    • "lofted_solid": a tapered/varying tube formed by stitching a sequence of 2D cross-section polygons placed along a 3D path. Defined by cross_sections (>= 2 CCW (u, v) polygons in the per-section local plane, all sharing the same vertex count) and section_centers (a list of 3D path origins, one per section). Adjacent rings are connected with quads (triangulated for the trimesh export) and the first/last sections cap the ends. This closes the gap between swept_profile (constant cross-section) and a free-form mesh — covers tapered handles, flared hoods, heat shrouds with varying inlet/outlet diameters, gun-stock necks that pinch and flare, and arch ribs whose cross-section evolves along the span. The cross-section's local Y aligns with the tangent of the path between adjacent section centers; local X/Z span the perpendicular plane.
    • "sdf_mesh": a raw triangle mesh produced by extracting the iso-surface of an F-Rep / SDF expression (typically via marching cubes from lathe.f_rep). Defined by mesh_vertices (an (N, 3) list of world-space coordinates, cm) and mesh_faces (an (M, 3) list of vertex indices). This is the bridge from the implicit-surface SDF authoring layer (mesh_program sdf_* ops) into the stable explicit-mesh vocabulary downstream stages already consume. Organic / creature / blob primitives — the kind of thing capsule/box/sphere booleans cannot express — round-trip through this type.
    • "component_assembly": a semantic compound primitive that stores a list of existing ShapePrimitive-compatible component records. It keeps high-level procedural solids such as vegetation, CGA facades, and modular assemblies as one object while still emitting visible exact geometry for each component.
    • "sdf_metaball_cluster": an extracted smooth-union organic SDF cluster that preserves metaball/F-Rep intent while carrying the concrete mesh vertices/faces needed by downstream explicit stages.
    • "terrain_mesh": a mesh-backed result of importing a terrain_patch through a geometry kernel while preserving biome, erosion, terrace, and heightfield intent alongside explicit vertices/faces.
    • "kernel_primitive_mesh": a mesh-backed result of importing a stable ShapeIR primitive through a geometry kernel while preserving the original primitive type in semantic metadata.
    • "instance_mesh": a mesh-backed result of repeat, distribute, copy-to-points, mirror, or scatter-on-surface placement programs that keeps instance/placement intent alongside explicit vertices/faces.
    • "component_assembly_mesh": a mesh-backed result of importing a semantic component assembly through a geometry kernel while preserving assembly kind, component count, and domain modifiers.
    • "profile_mesh": a mesh-backed result of importing profile, sweep, loft, polywire, helical, spring, curved-tube, threaded, or carve construction through a geometry kernel while preserving the profile-operation modifier payload.
    • "construction_feature_mesh": a mesh-backed result of importing visible hard-surface construction features such as trim bands, panel frames, brackets, mount plates, weld seams, and related detail primitives while preserving their v2 modifier payloads.
    • "edge_control_mesh": a mesh-backed result of importing hard-edge or weighted-normal edge-control operations while preserving the edge-operation modifier payload.
    • "polybevel_mesh": a mesh-backed result of sop.polybevel, op.bevel, or op.chamfer that keeps visible edge-treatment intent alongside explicit vertices/faces.
    • "hull_mesh": a mesh-backed result of op.hull that keeps convex-hull construction intent alongside explicit vertices/faces.
    • "minkowski_mesh": a mesh-backed result of op.minkowski that keeps Minkowski/shell-expansion intent alongside explicit vertices/faces.
    • "subdivision_mesh": a mesh-backed result of sop.subdivide that keeps subdivision/finishing intent alongside explicit vertices/faces.
    • "remesh_mesh": a mesh-backed result of sop.remesh that keeps remeshing/target-edge intent alongside explicit vertices/faces.
    • "deform_mesh": a mesh-backed result of twist/taper/bend deformers that keeps deformation intent alongside explicit vertices/faces.
    • "boolean_mesh": a mesh-backed result of kernel boolean composition that keeps union/subtract/intersect intent, attempted-vs-actual kernel metadata, seam groups, and explicit vertices/faces together.
    • "spring": a semantic helical wire coil with radius, tube_radius (wire radius), height, turns, optional axis, segments_per_turn, cross_section_segments, phase_degrees, and handedness. It preserves mechanical spring intent while emitting the same visible swept wire geometry expected by downstream stages.

    def to_dict(self) -> dict[str, Any]:
    """Serialize this primitive as a dict.

    Cached per-instance via ``_TO_DICT_CACHE`` (see module top) —
    ``asdict(self)`` deep-walks every dataclass field and is the
    single largest cost in v1 lowering (~13s of 174s in profiling).
    Within a build, the same primitive is to_dict'd many times by
    different downstream code paths; this caches the first result.
    """
    key = id(self)
    cached = _TO_DICT_CACHE.get(key)
    if cached is not None:
        return dict(cached)  # defensive copy so callers can mutate
    result = _CachedDict(asdict(self))
    _TO_DICT_CACHE[key] = result
    return dict(result)
