    Secret Hygiene Confirmations — Lathe v0.2.0rc1¶

    Phase 9 P0. Self-assessment. Reviewer: Tal Merri (@talmerri). Date: 2026-04-28.

    This document records the secret-hygiene confirmations performed during the v0.2.0rc1 readiness remediation pass. It pairs with docs/release/evidence-bundle-v0.2.0rc1/gitleaks-history.txt (Phase 9 full-history scan transcript), the existing docs/release/evidence-bundle-v0.2.0rc1/gitleaks.txt (Phase 6 working-tree scan transcript), the safe-logging tests at tests/unit/test_safe_logging.py, and the telemetry payload-hygiene tests at tests/unit/test_telemetry.py.

    • H40 — gitleaks must run on a host with the tool installed. Phase 6 H39 covers the working-tree scan; Phase 9 H40 covers the full-history --log-opts="--all" scan. Either install scoop/choco/go-installed gitleaks locally and rerun BOTH commands, OR rely on the .github/workflows/gitleaks.yml CI run after the branch is pushed and link the GitHub Actions run URL in both transcripts.
    • H41 — secret scan over tmp_gallery_phase7/<asset>/build_report.json must be rerun after Phase 7 lands. The expected answer is "no" because lathe/cli/build_cmd.py calls emit_build_ping only on the success branch and the build report itself is sanitized (tests/unit/test_telemetry.py:201-317). Confirm during Phase 7 follow-up.

    Secret rotation policy + scope minimization¶

    This is forward-looking: v0.2.0rc1 ships no first-party hosted credentials. The runtime-config schema allows operators to embed their own provider tokens (e.g. a Hunyuan provider's API key) but Lathe itself does not provision, distribute, or rotate any secret. The first-party attack surface for secret rotation is therefore zero today.

    Policy framework (forward-looking, requires-human ratification)¶

    When any first-party hosted credential surface ships, the following policy applies. All four sub-policies are requires-human: ratified before any hosted-credential surface ships in any channel — public, dev, staging, or behind a feature flag.

    1. Scope minimization. Every credential is bound to the narrowest scope it can do its job in. Telemetry ingest credentials write to the ingest endpoint only and have no read scope. Publish-driver credentials are bound to a specific S3 prefix or Supabase bucket and never to the parent account. Provider credentials are bound to a single base URL.
    2. Rotation cadence. Default rotation cadence is 90 days for credentials that are operator-rotated; 24 hours or shorter for credentials that are session/CI-issued (OIDC tokens for PyPI Trusted Publishing fall in the latter category — see EXC-PHASE3-PYPI-TP-002). Rotation logs MUST exist; "rotated when we remembered" is not acceptable.
    3. Storage. No long-lived secrets in source control. Any credential committed to the repo (intentionally OR accidentally) is treated as compromised and rotated immediately. Gitleaks CI gate (.github/workflows/gitleaks.yml) is the trip wire on commit/PR.
    4. Revocation surface. A documented runbook MUST exist for revoking any first-party credential within 1 hour of compromise notice. The runbook is owned by requires-human: (see auth attack-tree note — no hosted surface today, no runbook required today).

    Until that ratification¶

    • Operator-supplied secrets in runtime_config.json are the user's responsibility. Lathe redacts them from logs (tests/unit/test_safe_logging.py) and never persists them in the build cache or build reports (tests/unit/test_telemetry.py:201-317). Operators should follow their own organization's secret-handling policy.
    • No first-party credentials are required to use Lathe. The conservative offline path (reference_only.json runtime config) needs zero credentials. Provider configs are explicit opt-in.
