## ============================================================
## 5) Disposition
## ============================================================

# Decision: NO RELEASE EXCEPTION required for the lxml CVE.
# Reason:
#   - lxml is not declared anywhere in lathe's published manifests.
#   - It will not be installed by `pip install lathe==0.2.0rc1` from a
#     clean environment. (Verifiable from pyproject.toml + the
#     wheel-install-py311.txt transcript captured during Phase 3, which
#     did not pull lxml.)
#   - Only a developer who explicitly opts into a third-party extra (e.g.
#     `cyclonedx-python-lib[validation]`) would get lxml, and at that point
#     they are responsible for using a fixed version.
#
# Action taken in Phase 6:
#   - Recorded this finding in `release-gates-v0.2.0rc1.md` § Dependency
#     vulnerability.
#   - Appended a "Phase 6 follow-up (2026-04-28)" section to
#     `pip-audit-runtime.txt` documenting the disposition.
#   - The stale install in the local dev venv may be removed at the
#     developer's discretion (`pip uninstall -y lxml`); doing so is
#     cosmetic and not load-bearing for the release.
#
# Optional hardening (NOT a v0.2.0rc1 blocker, recorded only):
#   - SBOM regeneration after `pip uninstall -y lxml` would shrink the
#     captured SBOM. The current SBOM accurately reflects the dev-venv
