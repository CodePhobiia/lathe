# Asset and Dependency Provenance

This page records the reviewed provenance for checked-in reference assets,
generated test fixtures, and direct runtime dependencies used by Lathe release
candidates. It is intentionally conservative: if a new binary asset or direct
runtime dependency is added, the provenance table and tests must be updated in
the same change.

## Direct Runtime Dependencies

`pyproject.toml` is the source of truth for direct runtime dependencies. The
release metadata checker rejects URL, local-path, and editable runtime
dependencies so package provenance starts from named package specifiers.

| Dependency | Source | License signal reviewed |
| --- | --- | --- |
| `lark` | PyPI package metadata / lockfile | MIT classifier and package license file. |
| `jsonschema` | PyPI package metadata / lockfile | `MIT` license expression. |
| `numpy` | PyPI package metadata / lockfile | Composite SPDX license expression published by NumPy. |
| `Pillow` | PyPI package metadata / lockfile | `MIT-CMU` license expression. |
| `trimesh` | PyPI package metadata / lockfile | MIT classifier and package license file. |

Optional extras and transitive dependencies are reviewed through the release
SBOM and dependency scan outputs described in [Release provenance](provenance.md)
and [Dependency policy](../dependency_policy.md).

## Release Checklist

Before promotion, reviewers must confirm:

- every checked-in binary reference or fixture is listed above
- no third-party media has been copied into `examples/` or `tests/fixtures/`
  without a source URL, license, and redistribution note
- runtime dependencies are package specifiers from `pyproject.toml`, not local
  paths or direct URLs
- SBOM output is attached to the release record for transitive dependency
  review
