### What this build verification proves

- The pipeline plumbing (Phase 0 §4.5/§4.6 + Phase 1 §5.6/§5.9 + isoperimetric formula) is **demonstrably flowing through end-to-end**.
- The calibration anchor has moved: a chest that previously certified at 0.888 PASS now scores 0.861 FAIL with `certified: False`.
- The new validators score the chest's specific geometry as deficient: `curvature_distribution: 0.091`, `texel_density_consistency: 0.0`, `topology_class_compliance: 0.585`. The auto-repair loop is now meaningful for the first time.

### What this build verification reveals as still-open

- **Chest selector dispatch is not matching the chest's actual component records in production runs.** The selector rules added to `lathe/primitive_selector.py:225+` exist but `signature.primitive_selector` records `None` for the chest. Need to audit why the dispatch path produces zero upgrades for chest components in real builds.
- **Decimater logic is one-sided.** It fires only when the mesh exceeds target_quads. Chest emits 286 quads against a 12000-quad target — way under-budget — and the decimater (correctly) doesn't decimate. But the kernel side is producing far too few primitives. The next leverage point is the geometry density side, not the decimater side.
- **Hero diagnostic gate keys on `intent.asset_class`** but `brassbound_chest.lth` declares `features.density = hero` instead. Either normalize the chest source, or extend the gate to also recognize `features.density = hero`.

## Next Implementation Queue

### Phase 4 — Organic + animation forward vocabulary (12-18 month horizon per roadmap §8)
