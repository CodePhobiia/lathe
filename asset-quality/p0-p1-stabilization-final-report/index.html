    2. docs/asset-quality/lathe-implementation-northstar-current-audit.md

    6. Adding the 12 missing examples/**/*.lth entries (imagination-to-life demos) to docs/examples_catalog.md.
    7. Narrowing the long_provider_secret regex in tests/unit/test_docs_static_audit.py so it no longer matches Python identifier assignments such as token = _LOWERING_GEOMETRY_KERNEL or source_token = _repair_policy_source_token(policy). Real provider secrets in code are quoted string literals; the narrowed regex requires the value to be quoted and accepts base64 characters (+/=).

    3.2 ShapeIR op-set drift¶

    lathe/asset_quality/shape_ir_v2.py already defined a first-class ZONE_OPS frozenset containing op.material_zone, op.decal_zone, and op.wear_zone, and unioned it into ALL_OPS. The drift was in the docstring (still said "seven families") and in tests/unit/test_shape_ir_v2.py (the union/count assertion and the test_op_families_are_disjoint test both omitted ZONE_OPS).

    Fix: updated the module docstring to "eight families" with a ZONE_OPS entry, added ZONE_OPS to the test's union and disjointness assertions, updated the count from 83 to 86, and added a new test_zone_ops_exact_members so the zone family has the same depth of coverage as the other families.

    3.3 Asset-quality diagnostics¶

    Three coordinated changes:

    1. lathe/asset_quality/diagnostics.py: render-class renderer_unavailable findings (severity info, status renderer_unavailable) are no longer promoted into the warnings / recommendations streams. They remain visible in findings so dashboards still see them, but they no longer block clean-baseline assertions.
    2. tests/unit/test_asset_quality_diagnostics.py: the v1+ payload now has repair_routes and render_class_validators as top-level keys and the metrics dict includes the eight render-class validator scores. Tests updated to expect that. The test_findings_pair_metric_to_recommendation_for_multiple_warnings test now filters findings to severity == "warning" before asserting pair counts.
    3. docs/asset-quality/quality-diagnostics-v1.md payload-schema section rewritten to document the repair_routes field, the render_class_validators nested block, the new metric names, and the info-vs-warning severity rule.

    4. P0 Workstream B — Wedge Asset Evidence¶

    The wedge build was the original report's most-blocked item. The fix is two changes that, together, turn the previously-hanging path into a finite, deterministic, real-artifact path:

    1. Boolean engine pinning. lathe/exact_solids.py::_TRIMESH_BOOLEAN_ENGINE now picks manifold when manifold3d is importable.     4.3 Why package / export / preview are still blocked — and why this is acceptable¶

    The validator says certified: false because the asset's authored quality threshold (threshold = 0.84 in examples/industrial_crate.lth:160) is higher than the score the synthesizer can currently produce (~0.57). Raising the score requires changes to the procedural synthesizer (more parts, better attachment integration), not to the build pipeline. The build pipeline now does its job:

    1. Run shape → topology → uv → surface → optimize → physics → rig → interfaces deterministically.
    2. Run all validators, gather diagnostics, run repair loop, re-validate.
    3. If still under threshold, emit BuildError("Validation failed") with the validator diagnostics and exit non-zero.

    This is the contract examples/industrial_crate.lth:207 (assert score >= threshold) wants. Bypassing it would be the "narrowed claim / weakened gate" pattern the audit explicitly rules out. The honest closure of plan §10 criterion #5 is therefore: real artifacts through validate, pipeline-emitted block at package, exactly the asset-quality gap (not a kernel-perf gap) named and recorded.
