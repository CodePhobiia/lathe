    1. Baseline Verdict¶

    Original baseline checks passed for both fixtures, but original baseline builds did not produce visible artifacts.

    Original allowed claim:

    industrial_crate and mechanical_door parse/check successfully, but the build path is blocked in shape-stage exact boolean fusion before mesh, preview, validate, or package evidence exists.

    That original baseline blocker is now fixed in the current working tree. The updated allowed claim after the Sprint 0 runtime fixes is:

    industrial_crate and mechanical_door parse/check successfully, produce shape/topology/UV/surface/optimize/validate artifacts in bounded builds, and fail honestly at validation before package/export.

    Prior forbidden claim before the post-breakthrough implementation pass:

    Do not claim Sprint 0 has a passing crate package, passing guardrail package, before/after visual improvement, or export evidence yet.

    Historical allowed claim from the 2026-05-05 post-breakthrough implementation pass:

    industrial_crate and mechanical_door parse/check successfully in the 2026-05-05 evidence roots, execute high-count cutter booleans through a bounded Manifold full-CSG route, preserve watertight exact-boolean topology, pass validation, and produce package/export artifacts.

    The first implementation blocker was not a weak-looking crate. It was earlier and more structural:

    exact hard-surface fixture
-> ShapeIR / exact mesh path
-> trimesh boolean fusion
-> external or heavy boolean engine path
-> no bounded failure or emitted stage report
-> no visible artifact

    That blocker was addressed by adding bounded exact-boolean fallback, bounded preview rendering, direct UV fallback normals, and bounded geometry-integrity validation. The next blocker is no longer "no artifact." It is:

    artifact -> validate -> semantic fragmentation / toy-or-primitive failure -> no package/export

    The next implementation slice should use the produced artifacts and diagnostics to make the crate semantically less merged/primitive, then prove the guardrail does not regress.

    Outstanding gap — live full-backend before/after rendering¶

    The Python-level probe confirms the dispatch + auto-graph + 52-op ShapeProgram all work end-to-end. The live python -m lathe.cli build examples/industrial_crate.lth ... invocation that exercises the full kernel + boolean compile of those 52 ops did NOT complete in this session — the build hung in the shape stage's boolean kernel for >30 minutes with no shape-stage artifacts produced.

    This is a kernel-performance gap, not a substrate gap. The same 52-op program lowers correctly to v1 records, registers all the zone-op metadata, and produces a non-empty ShapeProgram in sub-second time at the synthesizer level. The bottleneck is in the boolean compile path the shape backend invokes downstream — likely related to the 16 op.union attached_to edges compounded with the solid primitives, the existing kernel's bounded-Manifold full-CSG route, and the increased op count vs the legacy scaffold path.

    Three honest paths to close this gap: 1. Profile + optimize the boolean compile for the 50+ op case. Likely the highest-leverage move once visible-quality work identifies what's actually slow. 2. Reduce the policy's expansion count for v1 (e.g., 4 corner brackets instead of 8, single-handle, no fastener) until the kernel handles larger programs gracefully. 3. Mark the auto-graph path as opt-in via the new procedural { auto_graph = enabled } Option-1 flag, and have industrial_crate.lth keep using the legacy scaffold until the kernel-perf work is done. This unblocks the Sprint 0 visible demo while the kernel performance work continues in parallel.

    The "before/after turntable.png comparison" the Sprint 0 done condition asks for is therefore deferred to a Cycle 4 Lane A kernel-performance pass. The substrate work (S0-1 through S0-6 + Capstone Options 1/2/3) is complete and verified at the Python / unit-test / contract-test level — what's outstanding is the multi-minute kernel run time, not the procedural correctness.

    Procedural-synthesizer opt-out (runtime config)¶

    lathe/shape/procedural_program_path.py::synthesizer_eligible now honors runtime_config.runtime.shape.synthesizer_disabled (bool or truthy string). When set, the synthesizer is short-circuited and the build proceeds through the certified legacy-scaffold path. This is the clean escape hatch for cases where the procedural synthesizer's kernel-perf gap on 50+ op programs would block live certification. Default behavior is unchanged: when the flag is unset (or runtime config is absent), eligibility is determined by procedural{} block, authored construction_graph, or registered FamilyAlias + parts.

    Example runtime_config.json:

    {
  "runtime": {
    "shape": {
      "synthesizer_disabled": true
    }
  }
}
